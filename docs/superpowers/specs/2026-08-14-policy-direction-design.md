# 외교정책 기조 — 설계

작성 2026-08-14. 이 문서가 유효한 스펙이다.
`specs/2026-08-14-agenda-entry-timeline-design.md` 와 `plans/2026-08-14-plan1-data-pipeline.md` 는
국회 회의록을 코퍼스로 삼던 시절의 것으로 **폐기**한다.

---

## 1. 무엇을 만드는가

외교백서 제1장의 **「외교정책 기조」 한 절만**을 1989~2025년치 모아,
정권 교체가 한국 외교의 우선순위 서술을 어떻게 바꾸는지 보여주는 자료와 화면.

정부는 매년 그 해 외교의 우선순위를 **번호를 붙여** 인쇄한다. 우리가 계산한 지표가 아니라
외교부가 매긴 순서다. 그 번호가 이 프로젝트의 유일한 척추다.

### 이미 확인된 것 (일곱 정부, 원문 대조 완료)

한반도·북핵 항목의 인쇄된 번호:

| 2001 | 2004 | 2011 | 2013 | 2018 | 2022 | 2025 |
|---|---|---|---|---|---|---|
| 김대중 | 노무현 | 이명박 | 박근혜 | 문재인 | 윤석열 | 이재명 |
| **1** | **1** | **1** | **1** | **1** | **1** | **4** |

여섯 정부 24년간 진보·보수를 가리지 않고 1번이었다가 2025년에 처음 내려간다.
정권이 바꾼 것은 순위가 아니라 이름과 방법이었다.

## 2. 답하려는 질문

**정권 교체는 외교정책 서술의 무엇을 바꾸고, 무엇을 바꾸지 못하는가.**

부수 질문:
- 교체의 **종류**(평시 / 같은 계열 / 여야 / 탄핵)에 따라 재편 폭이 다른가
- 전임 정부의 정책 이름은 어떻게 처리되는가 — 계승·개명·명시적 폐기·침묵
- 어떤 항목이 새로 생기고 어떤 항목이 사라지는가

## 3. 범위와 경계

### 이 스펙이 책임지는 것

원본 문서 → **검증된 데이터셋 `data.json`**

### 이 스펙이 책임지지 않는 것

`data.json` → 화면. **프런트엔드와 UX/UI는 Claude Design이 맡는다.**

### 경계 = 계약

두 쪽을 잇는 것은 §5의 JSON 스키마와 §8의 서술 규율 둘뿐이다.
스키마가 바뀌면 양쪽이 합의해야 하고, 서술 규율은 화면이 어떻게 생겼든 지켜야 한다.

### 하지 않는 것

- 백서 전문(약 12,000면) 처리 — 기조 절만 쓴다
- 국제정세전망 — 이 단계에서 쓰지 않는다
- 빈도 통계·워드클라우드·자체 산출 순위 지수
- 파이프라인 안의 LLM 호출 (§6 참조)
- DB — 정적 JSON만
- 우리 목소리의 인과 주장

## 4. 코퍼스

`data/<대상연도>/` 에 정리되어 있다. 상세는 `data/MANIFEST.md`, 기계용은 `data/manifest.csv`.

### 반드시 지킬 것 — 연도 명명이 중간에 뒤집힌다

| 제목 형태 | 대상 연도 |
|---|---|
| `YYYY 외교백서` | **YYYY − 1** |
| `YYYY년도 국제정세와 외교활동` | **YYYY** |

「2021 외교백서」(2020년)와 「2021년도 국제정세와 외교활동」(2021년)이 함께 존재한다.
**파일명 앞 네 자리로 정렬하면 전체가 한 해씩 어긋난다. 폴더명을 쓴다.**
각 문서 제1장 제목이 대상 연도를 직접 밝히므로(예: "2011년 국제 정세 및 외교정책 기조") 그것을 근거로 삼는다.

### 상태

- 전체 37개년(1989~2025), **연도 결손 없음**
- 즉시 사용 25 / OCR 필요 10(1989~1996, 2017, 2019) / HWP 3.0 파서 필요 1(2002) / 원본 손상 1(2004)

### 포맷 여섯 세대

| 대상연도 | 형식 |
|---|---|
| 1989~1996 | 스캔 이미지 PDF |
| 1997~1998 | MS Word 97 `.doc` |
| 1999~2001 | HWP 5.0 (OLE) |
| 2002 | HWP 3.0 (별도 형식) |
| 2003~2019 | 텍스트 PDF, 장별 분할 |
| 2020~2025 | 텍스트 PDF, 단일 파일 |

### 원본 자체의 결함 (재다운로드로 해결 안 됨)

외교부 아카이브 링크가 엉뚱한 파일을 준다. MD5로 재현 확인했다.

| 대상연도 | 없는 것 | 링크가 주는 것 |
|---|---|---|
| 1994 | 제1장 | 머리말 |
| 2001 | 제9장 | 제4장 |
| 2004 | 본문 대부분 | 8쪽 조각 |
| 2005 | 제4장 | 제1장 |
| 2007 | 제7장 | 부록 |

기조 절은 제1장(2002년 이후) 또는 제2장(2001년 이전)에 있으므로
**2004년을 제외하면 이 프로젝트에 영향이 없다.**
2004년은 발간사에 그 해 기조가 산문으로 남아 있어 그것으로 대체하고 출처를 다르게 표기한다.

## 5. 데이터 모델

### 단위

- **Edition** — 발간분 하나. 대상 연도와 1:1.
- **Priority** — 기조 절의 항목 하나. 인쇄된 번호를 그대로 가진다.
- **Stream** — 여러 해에 걸친 같은 줄기. 사람이 배정한다.
- **Link** — 인접 연도 항목 사이의 관계. 사람이 판정한다.

규모: 37개년 × 4~8항목 ≈ **180개 항목.** 전수 육안 검수가 가능한 크기다.

### `data.json` 스키마

```jsonc
{
  "meta": {
    "schemaVersion": 1,
    "builtAt": "2026-08-14",
    "coverage": { "from": 1989, "to": 2025, "verified": 7, "total": 37 }
  },

  "editions": [{
    "coverageYear": 2013,
    "title": "2014 외교백서",
    "publishedYear": 2014,
    "administration": "박근혜",
    "brand": "국민과 함께하는 신뢰외교",   // 없으면 null
    "section": { "chapter": 1, "section": 2, "label": "외교정책 기조", "pages": [23, 31] },
    "markStyle": "bullet",                 // number | ordinal-word | bullet | inline-lead | prose
    "status": "verified",                  // §5-1 참조
    "sourceFiles": ["2014 외교백서_제1장.pdf"],
    "note": null
  }],

  "priorities": [{
    "id": "2013-1",
    "coverageYear": 2013,
    "ordinal": 1,                          // 문서에 인쇄된 번호
    "title": "북핵문제 진전을 위한 동력 강화",
    "quote": "우리 정부는 한반도 신뢰프로세스 원칙에 입각하여 …",
    "stream": "peninsula",
    "source": { "edition": "2014 외교백서", "chapter": 1, "section": 2, "page": 24 },
    "flags": []                            // title-lost | from-preface | partial 등
  }],

  "streams": [{
    "id": "peninsula",
    "label": "한반도·북핵",
    "members": ["2001-1", "2004-1", "2011-1", "2013-1", "2018-1", "2022-1", "2025-4"]
  }],

  "links": [{
    "from": ["2011-4", "2011-5"],          // 빈 배열이면 신설
    "to": "2013-5",                        // null이면 소멸
    "relation": "merge",                   // inherit | rename | split | merge | new | dropped
    "note": "재외국민 항목과 공공외교 항목이 하나로 합쳐진다"
  }],

  "transitions": [{
    "coverageYear": 2013,
    "type": "same-bloc",                   // steady | same-bloc | opposition | impeachment
    "outgoing": "이명박",
    "incoming": "박근혜",
    "date": "2013-02-25"
  }]
}
```

`transitions` 는 **모든 대상 연도에 하나씩** 있다. 교체가 없던 해는 `type: "steady"` 다.
대조군을 화면에 같은 형식으로 놓기 위해서다 — "평시엔 이만큼 변하는구나"를 독자가 직접
비교하게 하는 것이 인과 주장을 피하는 방법이다.

### 5-1. `editions[].status` 의 뜻

| 값 | 뜻 | 화면에서 |
|---|---|---|
| `verified` | 기조 절 전체를 원문 대조로 확인 | 정상 표시 |
| `partial` | 일부 항목만 확인 (예: 2022년 1~4번까지) | 확인된 만큼만, 나머지는 비어 있음을 표시 |
| `from-preface` | 본문 손상으로 발간사에서 가져옴 (2004년) | 출처를 다르게 표기 |
| `pending` | 파일은 있고 아직 작업 안 함 | 빈 칸 |
| `blocked` | OCR·파서가 없어 작업 불가 (1989~1996 · 2002 · 2017 · 2019) | 빈 칸 + 사유 |

`priorities` 는 `verified` · `partial` · `from-preface` 인 연도에만 존재한다.
`pending` · `blocked` 연도는 `editions` 항목만 있고 `priorities` 가 비어 있다 —
**화면이 "아직 없음"과 "원래 없음"을 구별할 수 있어야 하기 때문이다.**

## 6. 파이프라인 — 모델을 넣지 않는다

```
data/            원본. 읽기만 하고 절대 수정하지 않는다
  ↓  extract/    포맷별 텍스트 추출 (규칙)
text/            <대상연도>.txt  +  <대상연도>.pages.json (쪽 경계)
  ↓  사람
authoring/       editions.tsv · priorities.tsv · streams.tsv · links.tsv
  ↓  verify.py   인용 원문 대조 — 실패하면 여기서 멈춘다
  ↓  build.py
data.json        → Claude Design 에게 넘긴다
```

### 왜 LLM을 안 쓰는가

1. **180개는 사람이 감당하는 양이다.** LLM은 사람이 못 하는 규모일 때 값을 한다.
2. **연결 판정은 검증할 수 없다.** 제목·인용은 원문 대조로 기계 검증되지만
   "같은 줄기인가"는 기계가 확인할 방법이 없다. 사람이 하면 그 구멍이 사라진다.
3. **그 판단이 곧 이 프로젝트의 주장이다.** 어차피 검수할 것이면 처음부터 직접 한다.
4. **재현된다.** 규칙 + 표는 몇 년 뒤 돌려도 같은 결과가 나온다.

작성 중 보조로 모델을 쓰는 것(초안 TSV 생성)은 무방하다. 저장소에 남는 것은
**사람이 확인한 표**이고 빌드 과정에는 모델이 없다.

### 추출기 — 포맷별

| 대상연도 | 도구 | 상태 |
|---|---|---|
| 2003~2025 (**2017 · 2019 제외**) | `pdftotext` (poppler). 2020~ 은 좌우 펼침이라 `-x/-W`로 반쪽씩 자른다 | 검증됨 |
| 1999~2001 | HWP 5.0 파서 (olefile + zlib + 레코드 파싱) | 작동 확인 |
| 1997~1998 | `.doc` (Word 97) | 미착수 |
| 2002 | HWP 3.0 | 미착수 |
| 1989~1996, 2017, 2019 | 스캔본 → OCR | 미착수 |

### 기조 절 찾기는 자동화하지 않는다

규칙 기반 추출을 시험했더니 절반도 못 잡았다. **항목 표기가 정부마다 다르기 때문이다.**

| 표기 | 연도 |
|---|---|
| 첫째·둘째·셋째 | 2001 |
| 아라비아 숫자 | 2011 · 2022 · 2025 |
| **글머리 기호** | 2013 |
| 리드 문장에 나열 후 본문에서 받음 | 2018 |
| 산문 (발간사) | 2004 |

하나의 정규식으로는 닿지 않는다. **연도마다 절의 위치와 표기를 사람이 한 번 확인하고
`editions.tsv` 에 기록한다.** 37개년이면 감당할 수 있는 양이고, 이 확인 자체가 자료가 된다
(`markStyle` 컬럼이 곧 "정부가 자기 항목에 이름 붙이는 방식"의 기록이다).

## 7. 검증 — 이 프로젝트의 심장

`verify.py` 는 `priorities.tsv` 의 모든 `title` 과 `quote` 가
해당 연도 `text/<연도>.txt` 에 **문자 그대로 존재하는지** 확인한다.

### 정규화 (양쪽에 동일 적용)

- 연속 공백·줄바꿈 → 공백 하나 (PDF 추출이 문장 중간에 줄바꿈을 넣는다)
- 중점 `·` `・` `∙` `･` → `·`
- 따옴표 `'` `'` `"` `"` → `'` `"`
- 폭 없는 문자·소프트하이픈 제거
- 낫표 `「」` 와 괄호 안 영문 병기는 **보존한다** (§9의 채굴 대상)

### 생략 표기

인용 안의 `(…)` 는 생략을 뜻한다. 이 표시로 잘라 **각 조각이 원문에 순서대로** 나타나면 통과.

### 실패 시

빌드를 **중단**하고 실패한 행을 전부 출력한다. 부분 성공으로 넘어가지 않는다.
손으로 옮겨 적는 방식의 유일한 약점이 오탈자인데, 이것을 기계가 막는다.

### 검증할 수 없는 것

`stream` 배정과 `links` 의 `relation` 은 사람의 판단이라 기계 검증이 불가능하다.
대신 **모든 연결에 근거 인용을 함께 기록하고**(`links[].note` 와 양끝 항목의 `quote`),
화면은 연결을 보여줄 때 양쪽 원문을 함께 제시해야 한다(§8).

## 8. 서술 규율 — 화면이 어떻게 생기든 지킨다

Claude Design 이 UI를 어떻게 만들든 아래는 계약이다.

1. **모든 항목에서 원문과 출처로 내려가는 경로가 있어야 한다.**
   출처는 발간분·장·절·쪽까지 표기한다.
2. **인용은 원문 그대로 보여준다.** 요약·의역·윤문 금지. 생략은 `(…)`로 표시.
3. **우리 목소리로 인과를 주장하지 않는다.**
   "정권이 바뀌어서 순위가 바뀌었다"(X) / "2025년 백서는 북핵을 4번에 두었다"(O)
4. **집계 통계·자체 산출 순위를 만들지 않는다.**
   화면에 나오는 숫자는 문서에 인쇄된 번호뿐이다.
5. **교체가 없던 해도 같은 형식으로 볼 수 있어야 한다.** 대조군 없이 교체만 보여주면
   독자가 인과를 읽게 된다.
6. **아직 채우지 않은 연도는 비어 있음이 보여야 한다.** 있는 것처럼 보간하지 않는다.
7. **정권을 정당 색으로 칠하지 않는다.** 색은 시간이나 줄기를 나타내고 정치적 함의를 넣지 않는다.

## 9. 확장 축 (2단계 이후, 같은 코퍼스에서 규칙으로 추출)

백서는 관공서 문체라 표기 규약이 엄격하다. **그 규약이 곧 스키마다.**

| 규약 | 뜻하는 것 | 추출 |
|---|---|---|
| 낫표 `「」` | 공식 정책명·문서명 | 정규식 |
| 영문 병기 `한글(English)` | 새로 들어온 개념 | 정규식 |
| 괄호 안 날짜 `(5.10)` | 사건 시점 | 정규식 |
| 작은따옴표 `' '` | 남의 말·신조어·유보 | 정규식 |

여기서 각각 정책 이름의 생몰 띠 / 개념의 수입·토착화 / 그 해 외교의 리듬이 나온다.
**전부 존재·부재·위치·시점이지 세어서 만든 수치가 아니다.**

## 10. 단계

### 1단계 — 2003~2025 (23개년)

포맷이 PDF 하나뿐이고 추출이 검증되어 있다. **여기서 완성품이 한 번 나온다.**

- 정권 이음매 5개: 2008 · 2013 · 2017 · 2022 · 2025
- OCR이 필요한 해가 둘(2017 · 2019) 있고, **2017은 교체 해라 반드시 해결해야 한다**
- 2004는 발간사로 대체
- 완료 조건: 23개년 `priorities.tsv` 작성 완료, `verify.py` 전건 통과, `data.json` 산출

### 2단계 — 1997~2002 추가 (29개년)
