# 국제 이벤트 × 정부·국회 의제 진입 기록 — 설계

> 2026-08-14 확정. 원 스펙("외통위 회의록 × 국제 이벤트 타임라인")에서 축 1개 추가,
> 프레이밍 1건 변경, 데이터 출처 전면 교체(스크래핑 → 공식 Open API).
>
> **이 문서의 모든 수치는 2026-08-14 실호출로 검증한 값이다.** 검증하지 않은 것은
> "미검증"으로 표시한다.

---

## 1. 한 줄 정의

국제 사안이 발생한 시점, **외교부 대변인 브리핑에 처음 등장한 시점**, **국회
외교통일위원회 회의록에 처음 등장한 시점**을 하나의 시간축에 놓고, 각 시점의 근거
원문과 함께 보여주는 웹 서비스.

## 2. 목표

- 이슈 8개에 대해 「발생일 → 정부 최초 언급 → 국회 최초 논의」 간격을 산출한다.
- 모든 수치에 원문 출처를 붙인다. 출처 없는 항목은 스키마 수준에서 거부한다.
- 근거를 찾지 못한 사안은 수치를 만들지 않고 상태로 표시한다.

## 3. 하지 않을 것

아래는 전부 **구현 중 자연스럽게 들어오려 하는 것들**이라 못 박는다.

1. **인과·평가 주장 금지.** "대응이 늦었다"가 아니라 "며칠 걸렸다"까지만 서술한다.
2. **특정 정당·의원에 대한 평가나 순위를 산출하지 않는다.**
3. **근거 없는 LLM 생성 문장을 출력하지 않는다.**
4. **집계 통계량 표시 금지.** 평균·중위·표준편차·순위를 화면에 띄우지 않는다.
   n=8은 모수 추정이 불가능한 표본이다.
5. **시차순 정렬 옵션을 제공하지 않는다.** 정렬 가능하게 만드는 순간 순위표가 되고
   3-2가 무너진다. 기본이자 유일한 순서는 **발생일순**이다.
6. **가지 개수를 지표로 쓰지 않는다.** 가지 높이를 발언량에 비례시키지 않고,
   "논의 5회" 같은 집계 수를 라벨로 띄우지 않고, 가지 수로 정렬하지 않는다.

### 측정 대상의 정확한 진술

원 스펙의 "국회에서 논의된 시점"은 **"외교통일위원회 회의록에 등장한 시점"**으로
좁혀 쓴다. 국회의 대외 의사표시는 결의안·본회의 대정부질문·의원외교로도 나가고
안보 사안은 국방위·정보위 소관일 수 있다.

서비스 정의를 "대응 시차"에서 **"의제 진입 기록(agenda entry record)"**으로 바꾼다.
시차를 1면에 두면 인과를 한 줄도 쓰지 않아도 독자가 평가로 읽는다. 1면은 최초 진입
기록과 발언 원문이고, 시차는 보조 수치다.

## 5. 데이터 — 3개 축

### 5-1. 국제 이벤트 축 (기준)

- **자동 수집(GDELT 등)을 쓰지 않는다.** CAMEO 코딩 오류와 소스 편중 때문에
  "발생일"이 실질적으로 "서구 언론에 크게 실린 날"이 된다.
- 이슈 8개를 수동 확정한다. 절차: 후보 12~15개 제시 → 사용자가 8개 선택.
- **회의록·브리핑에서 이슈를 뽑지 않는다.** 많이 언급된 주제를 이슈로 삼으면
  "논의된 것" 중에서만 선정하는 셈이라 "확인되지 않음"이 구조적으로 나올 수 없다.
- 선정 기준: (a) 발생일이 공적 기록으로 특정 가능, (b) 외통위 소관이 명확,
  (c) 2024-05-30 ~ 현재.

**발생일 출처 후보 (회의록과 독립):**

| 출처 | 내용 |
|---|---|
| 외교부 `대한민국외교연표`/`외교일지` (LOD) | 1962년부터. SPARQL·다운로드, 키 불요 |
| 외교부_양자조약 / 국가·지역별 주요협정정보 | 조약 체결·발효일 |
| 외교부_국가(지역)별 주요인사 교류 | 정상·장관 방문 일자 |
| 통일부_북한 약사 정보 | 북한 주요 연혁·사건 |
| 통일부_남북관계 남북합의서 | 합의서 체결일 |

**`data/events.json` 필수 필드:**

| 필드 | 설명 |
|---|---|
| `issue_id` | 슬러그 |
| `title` | 표시명 |
| `event_date` | 기준 사건 발생일 |
| `date_type` | `발표`/`서명`/`발효`/`공표`/`개시` |
| `source_url` | 공개 원본 URL |
| `description` | 1~2문장 — LLM 관련도 판정의 기준문 |
| `keywords` | 키워드·별칭·변칭 배열 |

`date_type`이 필수인 이유: 국제 사안은 사건이 아니라 **과정**이다. 관세 조치 하나만
봐도 후보 날짜가 발표일/서명일/발효일/한국 적용일로 최소 4개다. 어떤 종류의 날짜를
골랐는지 기록하지 않으면 서로 다른 종류의 날짜끼리 시차를 나란히 놓게 된다.
**8개를 가능하면 같은 유형으로 통일한다.**

### 5-2. 정부 축 — 외교부 브리핑

**스크래핑하지 않는다. 공식 API를 쓴다.**

| 데이터셋 | ID | 내용 |
|---|---|---|
| **외교부_브리핑** | `15141796` | 제목 · **내용(HTML 원문 전체)** · 첨부 · 작성부서 · 일자. 약 2,303건 |
| 외교부_보도자료 (보조) | `15141564` | 동일 구조 |

키 필요 · 무료 · 자동승인 · 개발계정 일 1만 건 · JSON/XML.

원본 화면(`https://www.mofa.go.kr/www/brd/m_4078/list.do`)은 스크래핑도 가능함을
실측했으나(User-Agent만으로 200, CSRF 불요) API가 있으므로 폴백으로만 남긴다.

**`I. 모두 발언`과 `Ⅱ. 질의 및 응답`을 반드시 구분한다.** 브리핑에 나왔다는 것이
"정부가 먼저 입장을 냈다"는 뜻이 아닐 수 있다 — 기자가 물어서 답한 것일 수 있다.
원문에 `<질문>`/`<답변>` 마커와 기자 소속·이름까지 있어 규칙으로 분리된다.

### 5-3. 국회 축 — 외통위 회의록

**스크래핑하지 않는다. 공식 API를 쓴다.** 기존 `National_Assembly_3` 인덱스도
재사용하지 않는다(사용자 결정).

**회의록은 한 API에 다 있지 않다. 회의 유형별로 분리돼 있다.**

| 유형 | 엔드포인트 | 필수 인자 | 외통위 22대 | 기간 |
|---|---|---|---|---|
| 상임위 전체회의 | `ncwgseseafwbuheph` | `DAE_NUM=22`, `CONF_DATE` | **54건** | 2024-07-17 ~ 2026-05-20 |
| **국정감사** | `VCONFAPIGCONFLIST` | `ERACO=제22대` | **31건** | 2024-10-07 ~ 2025-10-28 |
| 인사청문회 | `VCONFCFRMCONFLIST` | `ERACO=제22대` | **2건** | 2025-07-14 ~ 07-17 |
| 소위원회 | `VCONFSUBCCONFLIST` | — | 0건 | — |
| 공청회 | `VCONFPHCONFLIST` | `ERACO=제22대` | 0건 | — |

**총 87건이다.** `ERACO`는 `제22대` 형식이어야 한다(`22`는 "데이터 없음" 반환).

**세 API를 모두 수집해 하나의 회의 목록으로 합친다.** 이것을 놓치면 편향의 방향이
정해져 있다 — 국정감사는 5-4에서 "시차를 인공적으로 압축한다"고 지적한 바로 그 회의
유형이고, 국감 31건이 빠지면 **최초 논의가 국감에서 일어난 이슈의 시차가 실제보다
길게 나온다.** 한 방향으로만 틀린다.

(참고: `National_Assembly_3`이 크롤링한 PDF 56건에는 이 국정감사 31건이 없다.)

**`ncwgseseafwbuheph` 응답 필드:**

| 필드 | 용도 |
|---|---|
| `PDF_LINK_URL` | **공개 원문 PDF 직접 링크** — 8절 증거 패널 |
| `TITLE` | `제22대 제419회 제2차 외교통일위원회 (2024년 12월 16일)` |
| `CLASS_NAME` | 회의 종류 |
| `SUB_NAME` | **안건명** — 7-5의 탐지 보조 축 |
| `CONF_DATE` / `CONF_ID` / `CONFER_NUM` / `DEPT_CD` | 일자·식별자 (외통위 `DEPT_CD=9700409`) |
| `VOD_LINK_URL` | 영상회의록 |

**첫 회의일 2024-07-17은 확정 사실이다** — 공식 API와 기존 인덱스가 일치하므로
수집 누락이 아니라 실제 원구성 지연이다. 22대 개원(2024-05-30) 후 약 7주간 외통위
회의가 없었다. 이 구간 이벤트는 `unobservable`이다.

**PDF 추출은 필요하다.** `CONF_LINK_URL`의 `xml.do`는 HTML 팝업 뷰어이고 원문 XML을
반환하지 않는다(`type` 4종 시험). 발언 전문은 PDF에서 뽑는다.

**부속 API** (필요시): `VCONFDETAIL`(회의록 상세, `CONF_ID`),
`VCONFBLLLIST`(회의별 안건목록, `CONF_ID`), `WEBCASTVCONF`(영상회의록),
`nktulghcadyhmiqxi`(위원회 위원 명단 — 발언자↔정당), `ALLNAMEMBER`(의원 인적사항).

### 5-4. 회기·일정·결측 (필수 — 이 처리 없이 배포하지 않는다)

국회가 열려 있지 않은 기간 때문에 시차가 길어진 경우와 실제 논의 지연을 구분하지
못하면 그래프 전체가 오독된다. **그리고 회기 구간만으로는 부족하다.**

| API | 엔드포인트 | 실측 | 필드 |
|---|---|---|---|
| **회기정보** | `BILLSESSPROD` | 438건 | `ERACO` `SESS` **`SESS_BG_DT`(집회일) `SESS_ED_DT`(폐회일)** |
| **국회일정 통합** | `ALLSCHEDULE` | 2026년 2,400건 | `SCH_DT` `SCH_TM` `CONF_DIV` `CMIT_NM` `CONF_SESS` `CONF_DGR` |
| 위원회별 전체회의 일정 | `nttmdfdcaakvibdar` | 외통위 44건 | `MEETING_DATE` `SESS` `DEGREE` `TITLE` `LINK_URL2` |
| 의사일정공지 | `njlyptmbatwuwjtxf` | 50건 | `PDF_FILE_URL` `ATTACH_FILE_URL` |

**네 종류의 구간을 산출한다:**

1. **회기 구간** — `BILLSESSPROD`의 집회일~폐회일
2. **외통위 실제 개회일** — `ALLSCHEDULE`에서 `CMIT_NM='외교통일위원회'` 필터.
   **배경 음영의 실질 기준. 회기가 아니라 이쪽을 쓴다.**
3. **국정감사·예산심사 구간** — `CONF_DIV`·`CLASS_NAME` 기준
4. **회의록 결측 구간** — `ALLSCHEDULE` ∖ 회의록 API **차집합**

**왜 회기만으로 부족한가 (실측):** 기존 인덱스에서 **2024-12-16 → 2025-02-26,
72일 공백**이 나왔다. 회기 중 상임위 미개회라면 회기 음영으로는 설명되지 않는다.
그리고 월별 분포가 극단적으로 쏠려 있다 — **11월 13회(전체의 25%), 2월·5월 각 1회.**
국정감사가 시차를 인공적으로 압축한다.

**왜 결측 검출이 필수인가 — 두 원인이 겹치고 둘 다 편향 방향이 정해져 있다:**

**(a) 회의록 발간 시차 — 실측 약 3개월.**

| 일자 | 회의 | 회의록 |
|---|---|---|
| 2026-04-15 / 04-23 | 전체회의 | 있음 |
| **2026-05-20** | 전체회의 | **있음 — 코퍼스 상한** |
| 2026-05-21 ~ 08-10 | **회의 없음** (일정에도 없음, 83일) | — |
| **2026-08-11** | 전체회의 (제438회 임시회 제1차) | **없음 — 미발간** |
| 2026-08-19 | 전체회의 (예정) | — |

**코퍼스 상한 2026-05-20은 수집 방식의 한계가 아니라 발간 시차 자체다.** 어떻게
수집해도 확장되지 않는다. 최근 약 3개월은 구조적으로 관측 불가다.

**(b) 비공개·소위 회의.** 외통위는 안보 사안에서 비공개 회의를 열고 회의록이
공개되지 않거나 축약된다. 소위원회·공청회는 API 결과가 0건인데, 회의가 없었던 것인지
회의록이 없는 것인지 구분해야 한다. **민감할수록 비공개 비율이 높으니, 정작 활발히
논의된 사안이 "논의 안 됨"으로 나온다.** 무작위 결측이 아니라 **주제와 상관된 결측**이다.

## 6. 산출 지표

### 6-1. 결과 상태 3분법

국회 축·정부 축 각각에 대해:

| 상태 | 조건 | 표시 |
|---|---|---|
| `discussed` | 발생 후 논의·언급 근거 발견 | 시차 N일 + 출처 |
| `not_found` | 발생 후 **관측 가능한 회의/브리핑이 있었으나** 근거 없음 | "확인되지 않음 (관측 N회)" |
| `unobservable` | 발생 후 관측 기회 **0회** | "관측 불가 — 시차 산출 안 함" |

`unobservable`이 **개원~첫 회의(7주)**, **장기 미개회(83일 등)**, **회의록 미발간
(최근 3개월)**, **회의록 비공개**를 같은 장치로 처리한다.

정부 축은 브리핑이 주 2회이므로 `unobservable`이 사실상 발생하지 않는다.
**정부 축에는 회기 공백이 없다** — 그래서 "국회가 안 열려서"와 "아무도 안 다뤘다"를
가르는 기준이 된다.

### 6-2. 시차를 두 단위로

- `days_to_first` — 발생일 → 최초 논의일 (일). **두 축 모두.**
- `meetings_to_first` — 발생일 이후 **몇 번째 외통위 회의**에서 논의됐나.
  **국회 축만** — 브리핑은 주 2회 정기라 "회차"가 지연 정보를 담지 않는다.

후자가 회기 교란의 정량적 답이다. 90일 걸렸어도 그게 발생 후 첫 회의였다면 `1회차`다.

### 6-3. 정부·국회 격차

`gap_gov_to_nk = 국회 최초 논의일 − 정부 최초 언급일`

정부가 60일 뒤에 언급한 사안을 국회가 65일에 다뤘다면, 65일은 60일에 종속된 값이다.

## 7. 탐지 파이프라인

### 7-1. 임계값 하이퍼파라미터를 두지 않는다

원 스펙의 "임계값 이상만 논의됨으로 판정"은 위험하다. 320건 라벨로 임계값을 정하면
그 임계값은 320건에 과적합되고, 시차는 **최솟값**이라 임계값에 극도로 민감하다.

1. **키워드 사전 + 안건명으로 후보 수집** — 재현율 최대, 컷 없음
2. **임베딩 유사도로 정렬만** — 컷하지 않음 (보강 경로)
3. **회의 내 후보를 순서대로 LLM 판정**, 연속 `M`건 무관 판정 시 중단

**`M = 8` 고정, 튜닝하지 않는다.** 후보는 유사도 순이므로 관련 발언이 8건 연속 무관
판정 뒤에 나타나려면 정렬이 크게 실패한 경우다. `M`을 라벨셋으로 최적화하면 없애려던
과적합이 뒷문으로 돌아온다. 대신 9-2의 전수 검증에서 **early stopping 때문에 놓친
사례가 있었는지 사후 확인**하고, 발견되면 `M`을 올려 전체 재실행한다(`stage_meta` 기록).

### 7-2. 시간순 정방향 스캔

전역 랭킹이 아니라 시간순 스캔을 쓴다. 구하는 것이 최솟값이므로 전체를 랭킹해 상위를
보는 구조는 문제와 맞지 않는다.

```
이슈 e, 코퍼스 C(국회 87건 또는 정부 브리핑)에 대해:
  for 문서 in (e.event_date 이후 C의 문서를 날짜 오름차순):
      후보 = 키워드매치(문서, e) ∪ 안건명매치(문서, e) ∪ 유사도상위(문서, e)
      판정 = LLM(후보)                    # M=8 early stopping
      if 실질 논의 발견 and 최초 미확정:
          최초 = 이 문서
      # 가지를 전부 그리려면 최초 발견 후에도 스캔 계속
```

- **최솟값이 정의상 정확하다** — 앞에서부터 봤으므로 놓칠 수 없다.
- **9-2의 전수 검증이 공짜로 따라온다** — 발생일부터 최초 논의까지 문서를 이미 다 읽었다.
- 최악의 경우 8 이슈 × (87 회의 + 브리핑) 칸. 비용 수십 달러 수준.

### 7-3. 발생일 이전 처리

발생일 이전 문서는 후보에서 제외한다. 단 **−30일 창은 `pre_event`로 별도 기록**한다.
사전 논의가 있으면 시차 해석이 달라지므로 숨기지 않는다. **두 축 모두 적용**하며
시차 계산에는 들어가지 않고 증거 패널에서만 열람된다.

### 7-4. 실질/형식 구분

| 축 | 실질 (solid) | 형식·수동 (dashed) |
|---|---|---|
| 국회 | `core` — 실질 논의 | `mention` — 인사말·경과보고 나열·의사진행 |
| 정부 | `모두 발언` — 정부 선제 | `질의 및 응답` — 기자 질문에 답 |

국회 축은 LLM 이진 판정, 정부 축은 원문 섹션 구분으로 규칙 처리(LLM 불필요).
시차 대표값은 실질 기준. 형식 최초일도 함께 표기한다.

### 7-5. 안건명 축 (국회 전용)

`SUB_NAME`(안건명)을 세 곳에 쓴다.

1. **1차 필터** — 발언 전문을 읽기 전에 후보 회의를 좁힌다. LLM 호출이 준다.
2. **강한 신호** — 안건 상정은 `mention`과 질적으로 구별된다. `core` 우선 후보.
3. **재현율 보강** — 키워드가 놓친 회의를 안건명이 잡는다(그 반대도). 합집합을 쓴다.

**안건명 매칭만으로 `core`를 확정하지 않는다.** 상정되었어도 실제 논의 없이 넘어간
경우가 있으므로 발언 근거를 반드시 확인한다(3-3).

### 7-6. LLM 호출 캐시

```
cache/llm/{sha256(model + prompt)}.json
```

재실행 비용 0 / 회귀 테스트가 **API 키 없이** 실행 / 프롬프트 변경 시 해시가 바뀌어
판정 변화가 추적된다.

## 8. 화면

### 8-1. 세 영역

**상단 — 절대 시간축 맥락띠 (얇게).** 여기서만 실제 날짜를 쓴다. 2024-05 ~ 현재 축에
회의 87건을 **바코드 형태**로(개별 마커 대신 밀도), 배경에 5-4의 네 구간 음영,
이벤트 8개 발생 지점을 표시한다.

**중앙 — 가지 타임라인 (주 화면).**

- **y축 = 국제 이벤트 8개**, 발생일순 고정
- 각 이벤트에서 오른쪽으로 **줄기** — x축은 경과일
- 줄기 위 **눈금** = 외통위 회의가 열렸으나 논의 근거 없음
- **위쪽 가지 = 외통위 논의**, **아래쪽 가지 = 외교부 브리핑 언급**
- 첫 가지는 굵게 + 점 캡 (= 전수 검증된 최초 진입)
- 이후 가지는 얇게. dashed는 7-4의 형식·수동 구분
- 가지 높이는 전부 동일 (3-6)
- **줄기는 관측이 끝나는 지점에서 끊기고 표시가 붙는다.** 이벤트마다 관측 가능 기간이
  다르다. 짧은 줄기가 "대응이 없었다"가 아니라 "볼 수 있는 기간이 짧다"로 읽혀야 한다.
- **x축 상한 180일 고정.** 초과분은 줄기 오른쪽 끝에 남은 가지 수를 명시한다.

**x축 토글 — `경과일` ↔ `회의 순번`.** `회의 순번` 모드에서는 눈금이 균등 간격이 되고
날짜가 축에서 사라져 **회기 효과가 완전히 제거된다.** 스케일 함수 교체 하나로 구현되는
5-4 교란 문제의 가장 직접적인 답이다.

**하단 — 증거 패널.** 가지·눈금 클릭 시:

| 국회 축 | 정부 축 |
|---|---|
| 회의일 / 회의명 / **회의 유형** / 안건명 / 발언자 / 원문 발췌 / **공개 PDF 링크 + 쪽수** | 브리핑 일자 / **발언 구분** / 질문자 소속 / 원문 발췌 / 원문 링크 |

**이것이 실질적 1면이다.** 시차 숫자보다 이쪽이 검증 가능한 산출물이다.

### 8-2. 색 사용

- **이슈별 색 구분을 하지 않는다.** 각 이슈가 자기 행을 가지므로 라벨로 충분하다.
- 색은 **축 정체성**에만: 국회 = 파랑, 정부 = 주황. 2개 범주.
- 상태는 **형태**로 구분한다(굵기·점선·해치).
- 다크모드 필수. 모든 색을 CSS 변수로 두고 `prefers-color-scheme`로 전환.

## 9. 검증

### 9-1. 재현율이 정밀도보다 중요하다

출력이 **최솟값**이라 오류가 비대칭이다.

- 정밀도 오류(허위 탐지) → 시차를 **줄인다**
- 재현율 오류(최초 논의 누락) → 시차를 **늘린다**

최솟값은 평균과 달리 강건하지 않다 — **1건 누락으로 값이 바뀐다.** 실측: 외통위 회의
간격은 중위 7일이지만 평균 13.2일, **최대 72일**이고 30일 초과 구간이 6개다. 최초 논의
1건을 놓치면 시차가 다음 회의까지 밀리고, 긴 구간이면 수십 일이 통째로 틀린다.
**재현율 0.9는 "10% 오차"가 아니라 "8개 중 일부는 시차가 아예 틀림"이다.**

→ **임계값을 F1 최대화로 잡지 않는다. `recall ≥ 0.95` 제약 하 정밀도 최대화.**

### 9-2. 검증을 2단으로

| | 검증 방식 | 화면 표현 |
|---|---|---|
| **최초 진입** | **전수 검증** — 발생일부터 첫 가지까지 문서를 사람이 전부 읽음 | 굵은 가지 + 점 캡 |
| 이후 가지 | LLM 탐지 + 표본 검증 | 얇은 가지 |

시차를 지탱하는 주장은 첫 가지 하나다. 7-2의 스캔 구조 때문에 이미 그 구간을 다 읽었다.
**화면이 검증 수준의 차이를 구분해야 한다** — 안 그러면 검증된 주장과 자동 탐지 결과가
같은 무게로 보인다.

### 9-3. 라벨 = 골든 = 산출물 입력

`data/decisions.jsonl` 하나가 세 역할을 겸한다.

1. 정답 라벨셋 → LLM 판정과 대조해 정밀도·재현율 자동 산출
2. 골든 파일 → 회귀 테스트 기준
3. `timeline.json`의 유일한 입력 → 산출물 재현성

표본 라벨은 이슈당 20건 × 8 × 2축 = **320건**, **상위/경계/하위 3층 균등 추출**한다 —
상위만 뽑으면 재현율이 측정되지 않는다.

### 9-4. 측정 표류 방지

**라벨링 시작 전에 `data/rubric.md`에 판정 기준을 고정하고 라벨링 중 수정하지 않는다.**
수정이 필요하면 버전을 올려 전체 재라벨한다. 없으면 정밀도·재현율이 무의미하다.

### 9-5. 파서 품질 게이트를 재정의한다

전량 파싱 정확도를 게이트로 걸지 않는다. 실제로 쓰는 것은 **최종 인용되는 발언
수십 건의 발언자·쪽수**다.

| 안 하는 것 | 하는 것 |
|---|---|
| 전량 파싱 정확도 게이트 | 페이지 텍스트 **손실률 0** |
| 파서 버전 반복 | 화자 미상 턴 비율 상한 |
| 전체 턴 품질 통제 | **최종 인용 발언 전수 원문 대조** |

파서는 정규식으로 충분하다 — `◯이름 위원`, `◯위원장 …`, `◯외교부장관 …` 서식이 일정하다.

### 9-6. 테스트

- **단위 (pytest, 순수 함수)**: `TITLE` 파서(회기·차수·유형), 발언자 패턴, 브리핑
  섹션 분리, 3상태 판정, `days_to_first`·`meetings_to_first`, 회기 겹침,
  early stopping 경계, 회의록 3종 병합 dedup
- **골든**: `decisions.jsonl` → `timeline.json` 변환 고정 (LLM 없이)
- **스키마**: `timeline.json`을 `timeline.schema.json`으로 검증 (CI)
- **프론트**: vitest — 스케일 함수, 축 토글, URL 상태 왕복
- E2E 없음
- CI: pytest + tsc + vitest + 스키마 검증 + Pages 배포.
  **파이프라인은 CI에서 돌리지 않는다**(키·비용). 로컬 실행 후 산출물 커밋.

## 10. 구조와 스택

### 10-1. DB를 쓰지 않는다. 파일만.

규모가 발언 턴 수만 건 + 브리핑 수천 건이고 산출물이 정적이다. 임베딩을 numpy
`memmap`에 올려 코사인 유사도를 행렬곱 한 번으로 계산하면 전수 검색이 수십 ms다.
근사 검색이 아니라 **정확 검색**이라 재현율 손실이 없다 — 최솟값을 찾는 문제에서
ANN의 근사 오차를 감수할 이유가 없다.

Docker·PostgreSQL·pgvector·백엔드 서버·스키마 마이그레이션 전부 없음.

### 10-2. 청킹 단계를 두지 않는다

청크는 RAG 컨텍스트 윈도 때문에 존재한다. 회의 단위로 LLM에 넣으므로 **발언 턴이
자연 단위**다. 단계 하나와 오류원 하나가 사라진다.

### 10-3. 디렉터리

```
international_relations/
├── schema/timeline.schema.json      계약 — 0일차 확정
├── fixtures/timeline.sample.json    프론트 병렬화용 수기 데이터
├── pipeline/
│   ├── run.py            오케스트레이션 (--from, 입력 해시 기반 스킵)
│   ├── fetch_nk.py       회의록 3종 API → meetings.jsonl (PDF URL·안건명 보존)
│   ├── download_pdf.py   PDF_LINK_URL → data/raw/
│   ├── extract.py        PDF → pages.jsonl + 손실률 게이트   [pymupdf]
│   ├── parse.py          pages → turns.jsonl + 화자미상 게이트 [정규식]
│   ├── fetch_gov.py      외교부 브리핑 API → briefings.jsonl (섹션 분리)
│   ├── embed.py          → embeddings.npy
│   ├── calendar.py       회기·일정 API → sessions.json, 결측 구간 검출
│   ├── scan.py           ★ 시간순 정방향 스캔 → candidates.jsonl
│   ├── metrics.py        decisions vs candidates → 정밀도·재현율
│   └── build.py          decisions.jsonl → timeline.json (스키마 검증)
├── data/
│   ├── raw/              PDF 원본
│   ├── interim/          pages / turns / briefings (JSONL)
│   ├── events.json       이슈 8개
│   ├── keywords.json     이슈별 키워드 사전
│   ├── rubric.md         ★ 판정 기준 — 라벨링 전 고정
│   └── decisions.jsonl   ★ 사람 확정 판정
├── cache/llm/            프롬프트 해시 캐시
├── web/                  React 19 + Vite + TypeScript
└── tests/
```

**모든 단계 출력에 `stage_meta`** — 입력 해시 / 코드 버전 / 실행 시각 / 행수.
**조용한 유실 금지** — 결측이 생기면 기록하고 exit 1.

### 10-4. 프론트

- TypeScript + React 19 + Vite
- **차트 라이브러리를 쓰지 않는다.** `d3-scale` + `d3-time`만, SVG 직접 렌더.
- 상태 관리 라이브러리 없음. `useState` + **URL 쿼리 파라미터**.
- `timeline.json` 하나만 fetch. **git에 커밋한다.**
- GitHub Pages 배포.

### 10-5. 계약 우선 (0일차)

파이프라인이 끝나야 프론트를 시작하는 순차 구조는 위험하다. 0일차 산출물:
`schema/timeline.schema.json` + `fixtures/timeline.sample.json`(8개 중 2개를 손으로
채운 가짜 데이터: `discussed` 1건 + `unobservable` 1건). 이 시점부터 프론트와
파이프라인이 독립 진행한다.

```
├── briefings[]     브리핑: 일자, 원문 URL
└── issues[]
    ├── issue_id, title, event_date, date_type, source_url, description
    ├── nk   { status, days_to_first, meetings_to_first, observable_count,
    │          branches[] { date, kind(core|mention), verified, evidence{...} } }
    ├── gov  { status, days_to_first, observable_count,
    │          branches[] { date, kind(opening|qa), verified, evidence{...} } }
    ├── gap_gov_to_nk
    └── pre_event[]
```

`evidence`: 원문 발췌 · 발언자(또는 질문자 소속) · 쪽수 · 원문 URL.
**출처 없는 `branch`는 스키마 수준에서 거부한다.**

## 13. 알려진 한계 (README에 그대로 옮긴다)

1. **선택 편향의 방향이 정해져 있다.** "외통위 소관이 명확한" 사안만 고르면 정의상
   논의될 가능성이 높은 것만 남는다. 진짜 방치된 사안은 소관이 모호해 후보에서 빠진다.
   **이 서비스가 보여주는 시차는 하한(lower bound)에 가깝다.**
2. **n=8이다.** 평균·유형별 비교·추론이 불가능하다. 사례 제시이지 추정이 아니다.
3. **재현율은 pooled다.** 라벨은 키워드·안건명·임베딩이 찾아온 후보에만 붙는다.
   시드에 없는 표현으로만 언급된 발언은 영원히 라벨이 없다. 보고 값이 상향 편향이다.
4. **비공개 회의는 구조적으로 보이지 않는다.** 소위원회·공청회 회의록은 외통위
   데이터가 0건이다. 존재는 5-4의 결측 검출로 표시하되 내용은 알 수 없다.
5. **회의록 발간 시차 약 3개월.** 코퍼스 상한 2026-05-20 이후 열린 회의(2026-08-11
   확인)는 회의록이 없다. **최근 3개월 이벤트는 수집 방식과 무관하게 관측 불가다.**
6. **국정감사가 시차를 압축한다.** 회의 유형을 표기하되 국감 최초 언급이 "논의"인지는
   판단하지 않는다.
7. **외통위만 본다.** 결의안·본회의 대정부질문·의원외교, 국방위·정보위 소관은 제외.
8. **정부 축은 브리핑만 본다.** 외교부 내부 의사결정 시점이 아니라 **공개 발화 시점**이다.
   브리핑 이전의 비공개 대응은 측정되지 않는다.
9. **LLM 판정은 비결정적이다.** 캐시와 `rubric.md` 버전으로 추적하지만 경계 사례의
   판정이 재실행 시 달라질 수 있다.
