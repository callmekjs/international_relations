## 3. OCR — 한자 인식을 반드시 켠다

1989~1996년은 **국한문 혼용**이다. 한국어만으로 OCR 하면 한자 자리가 통째로
쓰레기가 된다. 실측(1990 외교백서 제1장 5쪽):

```
kor 만          짧시조"89 ※파을   /  %투프 구현  /  조.랫밴로  /  훼※빼가
kor+chi_tra     實用主開的 接近含  /  改革政策    /  至上課題冬 /  轉換期才
```

완벽하진 않지만(`主開` 는 `主義` 가 맞다) **쓰레기 → 읽을 수 있는 수준**이 된다.

- 언어팩은 이미 받아 두었다: `%LOCALAPPDATA%\tessdata\` 에 `kor` `chi_tra` `chi_sim`
- 속도: `kor` 2.3초/쪽 → `kor+chi_tra` **6초/쪽** (2.6배)
- CPU 로 3,585쪽 = **약 6시간**

### GPU 로 갈아탈 것

이 노트북에 **RTX 5070 (8GB)** 이 있고 `torch 2.11.0+cu128` 이 설치돼 있다.
Tesseract 는 GPU 를 못 쓰므로 다른 엔진으로 바꾼다.

```
후보   EasyOCR (torch 기반, 설치 간단) / PaddleOCR / Surya
목표   6시간 → 40분
조건   갈아타기 전에 같은 쪽으로 Tesseract 와 품질을 비교할 것
       1989년 국한문 혼용 쪽으로 시험해야 의미가 있다
```

## 4. 한자 — 원문을 지우지 말 것

사용자 지시: 한자를 한글로 바꿔서 넣되 **원문도 남긴다.**

```
원문칸    北韓의 對外政策
한글칸    북한의 대외정책     ← 분석·그래프는 이걸 쓴다
```

### 함정

```
1989~1996 본문 (국한문 혼용)
  北韓의 對外政策   →  북한의 대외정책      맞다

2000년대 괄호 병기
```

**괄호 안 한자는 건드리지 않는다.** 앞에 한글 표기가 이미 있는 경우가 대부분이다.

도구: `pip install hanja` (아직 설치 안 함). **`requirements.txt` 에 적을 것.**

## 5. 검증 방식이 근본적으로 달라진다 ⚠ 가장 중요

```
지금까지   사람이 141개를 옮겨 적음  →  기계가 글자 대조  →  100% 보장
앞으로     11,324쪽을 사람이 옮겨 적을 수 없음  →  무엇으로 보장하나?
```

"글자가 맞나"를 볼 수 없으므로 **"빠진 게 없나"**를 본다.

### 한 해씩 끊어서 통과시킨다 ⚠ 사용자 요구 · 오늘 가장 비쌌던 실수

**한 해가 검사를 통과하지 못하면 다음 해로 넘어가지 않는다.**
그 해 산출물을 지우고, 원인을 고치고, 그 해만 다시 돌려 통과시킨 뒤에 넘어간다.

```
for 연도 in 1989..2025:
        추출  →  검사
                  │
                  ├─ 통과 →  다음 연도
                  │
                  └─ 실패 →  ① 그 해 산출물만 삭제
                             ② 실패 사유 출력하고 멈춤
                             ③ 사람이 원인을 고침
                             ④ 그 해만 다시 돌림  ↺
```

**왜 이렇게 하나 (2026-08-15 실측)**

오늘은 28개년을 다 뽑은 뒤에 검사했다. 그 결과

- 머리글이 문장을 파고드는 것을 마지막에 발견 → **28개년 전부 다시 추출**
- 세로쓰기 머리글을 지우려다 본문이 깎인 것을 발견 → **또 전부 다시**
- 쪽번호를 더 건지려다 망가진 것을 발견 → **또 전부 다시**

**세 번 전량 재처리했다.** 한 해씩 끊었다면 첫 해에서 잡고 고친 뒤 나머지를
한 번만 돌리면 됐다. 전문 ETL 은 37개년 11,324쪽이라 전량 재처리 한 번이
**한 시간을 넘긴다.** 같은 방식으로는 안 된다.

**설계 조건**

| 조건 | 이유 |
|---|---|
| 연도별 산출물을 폴더로 격리 | 한 해만 지우고 다시 돌릴 수 있어야 한다 |
| `--year 2013` 으로 한 해만 실행 | 전량 재처리를 피한다 |
| 실패하면 그 해 산출물 자동 삭제 | 반쪽 결과가 남아 '완료'로 오해되면 안 된다 |
| 실패 사유를 그 자리에서 출력 | 무엇을 고쳐야 하는지 바로 보여야 한다 |
| 통과한 해는 다시 안 건드림 | 이미 통과한 것을 다시 돌리면 시간만 든다 |

**무작정 다시 돌리지 않는다.** 아무것도 안 바꾸고 재시도하면 같은 결과가 나온다.
지우고 다시 돌리는 것의 값은 **한 해만 빠르게 고쳐 다시 볼 수 있다**는 데 있다.

**통과할 수 없는 해는 따로 적는다**

2016년처럼 원본이 결손이면 영원히 통과하지 못해 전체가 멈춘다.
`config/known_issues.tsv` 에 **연도 · 사유 · 승인일**을 적고, 거기 있는 해만
'알고 있는 예외'로 통과시킨다. 코드에 박지 않는다 — 사유가 남아야 한다.

### 점검 2층 (사용자 요구)

## 6. 오늘 알아낸 함정 — 다시 겪지 말 것

**연도 명명이 중간에 뒤집힌다**

| 제목 | 대상 연도 |
|---|---|
| `YYYY 외교백서` | **YYYY − 1** |
| `YYYY년도 국제정세와 외교활동` | **YYYY** |

「2021 외교백서」(2020년)와 「2021년도 국제정세와 외교활동」(2021년)이 함께 있다.
**파일명으로 정렬하면 전체가 한 해씩 어긋난다. 폴더명을 쓴다.**

**좌우 펼침은 연도로 판단할 수 없다**
2015년은 1장만 단면이고 2~7장이 펼침이다. **쪽 폭 > 700pt 로 판정**한다.

**폰트가 글리프를 엉뚱한 코드에 심는다**

| 뽑힌 것 | 실제 | 연도 |
|---|---|---|
| `㤚` | `李` | 2003·2004 |
| `₩` | `·` | 2008·2009 |
| `䞺` | `fi` | 2021 |
| `李` U+F9E1 | `李` U+674E | 호환용 한자. 눈으로 구별 불가 |

교정표가 `config/text_repairs.tsv` 에 근거와 함께 있다. **살려서 쓸 것.**

**공백이 통째로 사라지는 해가 있다** — 2003년 공백률 8.0%.

**쪽 머리글이 문장 한가운데를 파고든다**
반복되는 줄을 세어 걷어낸다(`dehead.py`). 세로쓰기 머리글은 글자가 한 자씩
흩어져 안 걸러진다.

**두 번 물린 것 — 반복하지 말 것**

1. 세로쓰기 머리글을 블록 크기로 걸러냈더니 본문이 10~30% 깎였다.
   2005년 인용 3건이 깨져 verify 가 잡았다.
2. 머리글에 붙은 쪽번호를 건지려고 비교 전에 앞뒤 숫자를 떼어냈더니,
   본문 줄에서도 숫자가 떨어져 나가 쪽번호가 오히려 줄고(2020년 352→175)
   2012·2018년 인용문이 깨졌다.

**둘 다 "머리글을 더 지우려다" 본문을 잃은 경우다.** 지우는 쪽으로 손대기 전에
검증부터 세워둘 것.

**2016년 원본 결손** — 「2017 외교백서」 제1장 PDF 에 인쇄 22~23쪽이 없다.
제1장은 21쪽에서 끝나고 제2장은 24쪽에서 시작한다. `MANIFEST.md` 미기록.

**2021년은 편제가 다르다** — 「2021년도 국제정세와 외교활동」에는 「외교정책 기조」
절이 아예 없다. 전문 ETL 에서는 문제되지 않지만 장·절 구조가 다르다는 표시가 된다.

## 6-B. 폴더 구조 — 산출물이 어디로 가나

사용자 결정(2026-08-15): **전체 삭제가 아니라 부분 수정으로 간다.**
파일 읽는 도구는 그대로 두고, 뽑는 범위와 검증만 새로 짠다.

```
data/                원본. 절대 안 건드린다
  1989/ … 2025/

out/                 ★ 한 해씩 작업하는 곳
  2013/
    pages.jsonl        쪽별 원문
    paragraphs.jsonl   문단별 (계층 정보 포함)
    meta.json          그 해 정보 + 검사 결과
  2014/
  …                    검사 실패하면 이 폴더만 통째로 삭제

corpus/              ★ 37개년 다 통과한 뒤에만 생긴다
  paragraphs.jsonl     전체 문단 한 파일
  by-admin/
    김대중.jsonl  노무현.jsonl  이명박.jsonl  박근혜.jsonl
    문재인.jsonl  윤석열.jsonl  이재명.jsonl
    (노태우.jsonl  김영삼.jsonl)
  index.json           몇 개년·몇 문단·어디가 OCR 유래인지

reports/             검사 기록
scripts/
  lib/                 살린 도구. 손대지 않는다
    word97.py  hwp3.py  formats.py  ocr.py
    dehead.py  normalize.py  stage_io.py
  extract.py           새로
  check.py             새로
  build.py             새로
```

**`out/` 은 작업장, `corpus/` 는 완성품이다.**
`corpus/` 가 존재한다는 것 자체가 "검사를 다 통과했다"는 뜻이 되게 한다.
미완성인 채로 분석에 들어가는 것을 막기 위해서다.

### paragraphs.jsonl 한 줄의 생김새

```jsonc
{
  "id": "2013-ch2-s1-p014",
  "연도": 2013,
  "정권": "박근혜",
  "발간분": "2014 외교백서",
  "장": 2, "장제목": "한반도 평화와 안정 유지",
  "절": 1, "절제목": "한반도 정세의 안정적 관리",
  "쪽": 32,
  "원문": "정부는 출범 이후 한반도 신뢰프로세스를 일관되게…",
  "한글": "정부는 출범 이후 한반도 신뢰프로세스를 일관되게…",
  "출처파일": "2014 외교백서_제2장.pdf",
  "OCR유래": false
}
```

| 왜 이 형태인가 | |
|---|---|
| 한 줄 = 한 문단 | 엑셀·파이썬·그래프 도구가 바로 먹는다 |
| 정권이 각 줄에 | "이명박 정부 문단 다 줘" 가 한 줄로 된다 |
| 장·절·쪽이 각 줄에 | 지식 그래프의 점과 선이 바로 나온다 |
| 원문·한글 두 칸 | 분석은 한글로, 인용은 원문으로 |
| OCR유래 표시 | 오탈자를 감안해야 할 문단을 구별한다 |

## 8. 순서와 시간

```
[1] 계획 확정 · 옛 산출물 정리                    20분
[2] GPU OCR 설치 + 1989년 쪽으로 품질 비교         40분
[3] 새 추출기 + 연도별 검사 (한 해 단위로 돌게)    2~3시간
[4] 시험용 한 해로 통과시키기 (2013년 권장)        30분   ← 여기서 다 잡는다
[5] 나머지 36개년 — 한 해씩 통과시키며 진행        1~2시간  일부 자동
[6] 한자 → 한글 칸 만들기                          40분
[7] 정권별로 묶기                                  40분
[8] 최종 검토 (분석 들어가기 전)                    40분
```

**합계 6~7시간.**

**[4] 가 핵심이다.** 한 해를 완전히 통과시키기 전에는 [5] 로 넘어가지 않는다.
오늘의 교훈이 그것이다 — 28개년을 다 돌린 뒤 문제를 찾아 세 번 전량 재처리했다.
한 해에서 다 잡고 나면 나머지는 대개 그대로 통과한다.

시험용으로는 **2013년**이 좋다. 장별 분할 PDF · 단면 · 글자 있음 으로 가장
평범하다. 그 다음 **2020년**(펼침 단일파일), **2002년**(HWP 3.0),
**1990년**(스캔·국한문) 순으로 까다로운 것을 하나씩 통과시키면
나머지는 이 넷 중 하나를 닮아 있다.

집에서 할 때는 **[2] 를 먼저 걸어두고** 그 사이에 [3] 을 짜는 것이 빠르다.
노트북이 절전으로 들어가면 멈추므로 전원 설정을 확인할 것.
