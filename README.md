# 외교의 순서

대한민국 외교백서 **37개년(1989~2025)** 전문을 기계가 읽을 수 있게 만들고,
그 위에 **정책 실무자를 위한 화면 넷**을 올린 프로젝트.

정부는 해마다 그 해 외교의 우선순위를 **번호를 붙여 인쇄한다.**
이 프로젝트가 보여주는 숫자는 그 번호다. 우리가 계산한 지표가 아니라
외교부가 매긴 순서다.

> **숫자를 지어내지 않는다.** 모든 값은 원본을 세어서 나온다.
> 못 읽은 것은 못 읽었다고 적고, 정확도는 반드시 함께 밝힌다.

## 무엇이 보이는가

### 1. 한반도는 언제 1번이 아니었나

37개년 중 **10번** 밀렸고, 밀린 이유가 서로 다르다.

| 연도 | 1번을 차지한 것 | 사정 |
|---|---|---|
| 1991 | 한·미 관계의 강화 | 유엔 가입을 앞둔 해 |
| 1992 | 대우방 관계의 발전적 강화 | 북방외교 마무리 |
| 1996·1997 | 세계화 외교 | '세계화' 구호가 외교 1번이 됨 |
| 1998 | 경제위기 극복 및 재도약 기틀 마련 | IMF 외환위기 직후 |
| 2015 | 전략적 로드맵에 따른 주변국 외교 | — |
| 2017 | 주변 4국과 정상외교 공백 복원 | 탄핵으로 생긴 정상외교 공백 |
| 2020 | 우리 국민의 생명과 안전 보호 | 코로나19 |
| 2021 | 코로나19 극복을 위한 외교 | 코로나19 |
| **2025** | 국익 중심 실용외교 기반 구축 | **외부 충격 없이, 그것도 4번까지** |

외환위기·탄핵·코로나가 밀어낸 해는 사정이 분명하다. **2025년만 그런 사정 없이
내려갔다.** 이 차이를 우리가 말로 설명하지 않는다. 배치로 보여주고 판단은 독자가 한다.

### 2. 정권이 바뀌면 외교가 바뀌는가 — 잰다

해마다 낱말 분포를 만들어 이웃한 해끼리 거리를 쟀다(코사인 거리, 34쌍).

```
같은 정권 안 이웃한 해   0.2026
정권이 바뀌는 해         0.2653
→ 정권 교체 때 1.31배 크게 달라진다
```

**그런데 1위는 정권 교체가 아니다.**

```
2019 → 2020   0.6568   문재인 정부 안   ← 코로나. 2위의 두 배 가까이
                        새로: 코로나·방역·화상·비대면
                        사라짐: 국빈·아세안·외교장관회담
1997 → 1998   0.1591   김영삼→김대중    ← 34쌍 중 23위. IMF 한복판이라 안 바뀜
```

정권 교체 8건 중 6건이 상위 11위 안에 든다. **"대체로 바뀐다 — 다만 코로나가
더 컸고, IMF 때는 안 바뀌었다."**

⚠️ **낱말이 달라진 것이 곧 정책이 달라진 것은 아니다.** 대통령·장관 이름도
낱말이라 정권이 바뀌면 반드시 달라진다. 이 수치는 "얼마나 달라 보이나"이지
정책의 옳고 그름이 아니다.

### 3. 한 정책의 생애가 보인다

```
1989   북방외교의 추진            3번
1990   북방외교의 지속적 추진      3번
1991   북방외교의 내실화          2번
1992   북방외교의 마무리와 내실화   2번
```

추진 → 지속 → 내실화 → 마무리. 4년에 걸친 한 정책의 일생이 순위와 함께 남아 있다.

### 4. 표기 방식도 여덟 번 바뀐다

| 표기 | 해 |
|---|---|
| 1. 2. 3. (`number`) | 14 |
| 첫째·둘째 (`ordinal-word`) | 6 |
| 문장 속 나열 (`inline-lead`) | 6 |
| ▲ 글머리 기호 (`bullet`) | 5 |
| 산문 (`prose`) · 소제목 (`heading`) | 각 2 |
| 정책목표 Ⅰ~Ⅴ (`roman`) · ①~⑤ (`circled`) | 각 1 |

**이 표 자체가 자료다.** "정부가 자기 우선순위에 이름 붙이는 방식"의 연대기다.
`authoring/editions.tsv` 의 `markStyle` 에 기록한다.

## 어떻게 만드는가 — 층이 둘이다

```
data/ 원본 268개
  │
  ├─[A] etl.py ─→ corpus/           기계가 읽는 전문 (문장 64,550 · 표줄 59,551)
  │                 ├→ index.py     목차 색인 932절
  │                 ├→ mine_entities.py  지식그래프 (개체 139 · 관계 1,400)
  │                 └→ policy_shift.py   변화량 34쌍
  │
  └─[B] extract.py ─→ text/         대조용 글월
                        │
                  사람이 원본을 보고 옮겨 적는다
                        ↓
                   authoring/       ← 저장소의 본체
                        ↓
                   verify.py        인용이 원문에 글자 그대로 있는가
                        ↓
                   build.py ─→ data.json ─→ web-demo
```

**[A] 는 기계가 전부 읽는 층**이고 **[B] 는 사람이 확인해 적는 층**이다.
둘은 목적이 다르다 — [A] 는 넓게, [B] 는 정확하게.

> ⚠️ **한 층을 고치면 다른 층도 따라가야 한다.**
> 2026-08-16 에 [A] 만 고치고 "끝났다" 고 보고했다가, 사이트가 여전히 옛 범위
> (1998~2025)를 보여주고 있는 것을 뒤늦게 발견했다(에러노트 38번).

### 추출 손상이 화면에 닿지 않는다

```
PDF ──추출──▶ text/          (㤚鵬, 공백 소실, OCR 오탈자 — 손상 있음)
                  │
                  └──▶ verify 가 대조용으로만 쓴다
                                  ▲
사람이 원본 보고 타이핑 ──▶ authoring ──▶ data.json ──▶ 화면
                             (李鵬, 정상)
```

화면에 나가는 인용문은 **사람이 원본을 보고 친 것**이고, 추출 텍스트는
**그것이 맞는지 검사하는 용도**로만 쓴다. 그래서 PDF 가 `李` 를 `㤚` 로 뽑아도
독자가 보는 글자는 멀쩡하다.

### 검증이 심장이다

`verify.py` 는 모든 `title` 과 `quote` 가 그 해 원문에 **글자 그대로** 있는지
확인하고, 하나라도 어긋나면 **빌드를 멈춘다.** 절반만 맞는 자료는 틀린 자료다.

**기계가 못 읽는 쪽은 어떻게 하나.** 1989~1991년 스캔본은 굵은 한자 제목을
글자 인식이 못 읽는다(300·500dpi × psm 3·4·6 전부 시험 — 핵심어 6개 중 1개).
그런 줄은 대조를 우회하되 **대신 다른 것을 요구한다.**

```
보통 줄              "이 글자가 원문 글월에 있다"       기계가 확인
flags=from-scan     "이 파일 이 쪽에 있다"            사람이 열어볼 수 있다
flags=page-cited    같음 (대조용 글월에 없는 장)
```

`srcPage` 를 안 적으면 검사에서 실패한다. **보증의 성질이 바뀐 것이지
사라진 것이 아니다.**


## 포맷 일곱 세대

37년 동안 일곱 가지 포맷으로 나왔고, 세대마다 읽는 법이 다르다.

| 대상연도 | 형식 | 읽는 법 |
|---|---|---|
| 1989~1996 | **국한문 혼용 스캔본** | `lib/ocr.py` — Tesseract `kor+chi_tra`, 300dpi |
| 1997 | MS Word 97 | `word97.py` — FIB → 조각표(piece table) 추적 |
| 1998~2000 | HWP 5.0 (OLE) | `formats.py` — olefile + zlib raw inflate |
| 2001 | HWP 3.0 | `hwp3.py` — raw deflate + 조합형, **본문 바이트 순서가 뒤집혀 있다** |
| 2002~2018 | 텍스트 PDF, 장별 분할 | PyMuPDF |
| 2016·2018 | 스캔 이미지 PDF | `lib/ocr.py` |
| 2019~2025 | 텍스트 PDF, 단일 파일 | PyMuPDF |

### 겪은 함정들

**연도 명명이 중간에 뒤집힌다**

| 제목 형태 | 대상 연도 |
|---|---|
| `YYYY 외교백서` | **YYYY − 1** |
| `YYYY년도 국제정세와 외교활동` | **YYYY** |

「2021 외교백서」(2020년)와 「2021년도 국제정세와 외교활동」(2021년)이 함께 있다.
**파일명 앞 네 자리로 정렬하면 전체가 한 해씩 어긋난다.** 폴더명을 기준으로 쓴다.

**목차가 세 군데에 있다**

| | 어디에 | 해 |
|---|---|---|
| ① | 목차 전용 파일 | 목차파일에서 257줄 |
| ② | 장 파일 안에 든 목차 쪽 | 397줄 |
| ③ | 본문의 제목 줄 | 450줄 |

1997~2000년은 목차가 **정말 없다**(파일 전체에 '목차'·'目次' 가 0회).
본문 제목으로 되만들었고, 목차가 있는 22개년으로 채점해 **89.9%** 를 확인했다.

**같은 제목이 세 가지 모양으로 인쇄된다**

```
① 제1절 국제 정세 개관        한 줄
② 제1절 / 국제 정세 개관      두 줄로 나뉨   2003·2009~2025년 507줄
③ 第1節 世界의 主要情勢        한자          1989~1992년 451줄
```

한 가지만 알아보던 탓에 **6개년의 목차가 통째로 비어 있었다.** 셋 다 받게 고쳐
문장에 절 제목이 붙는 비율이 **67.1% → 97.6%** 가 됐다(에러노트 33번).

**좌우 펼침은 연도로 판단할 수 없다**

2015년은 1장만 단면이고 2~7장이 펼침이다. **쪽 폭(> 700pt)으로 판정**한다.

**폰트가 글리프를 엉뚱한 코드에 심어놓는다**

| 추출된 것 | 실제 | 연도 |
|---|---|---|
| `㤚` | `李` | 2003·2004 |
| `₩` | `·` 중점 | 2008·2009 |
| `䞺` | `fi` 합자 | 2021 |
| `李` U+F9E1 | `李` U+674E | 호환용 한자. 눈으로 구별 불가 |

**'인도적'이 나라 인도로 잡힌다** — `인도` 로 시작하는 말 3,578회 중
**838회(23%)** 가 나라가 아니었다(인도적 670 · 인도주의 98 · 인도양 66).
찾을 때만 가리고, 보여줄 문장은 원문 그대로 둔다.

**쪽 머리글이 문장 한가운데를 파고든다** — 세로쓰기 머리글은 글자가 한 자씩
흩어져 걸러지지 않는다. 그 자리는 인용에서 `(…)` 로 끊는다. 생략 표시이자
"여기서 머리글이 끼어든다"는 기록이다.

|---|---|

### 알려진 한계

측정으로 확인된 것만 적는다.

**1. 관계 종류가 87% 는 '모름'이다**
근거 0개가 63%인데, 대부분 *"멕시코, 브라질, 인도 등"* 같은 **나열**이다.
근거만 있으면 81% 를 붙인다. 문턱을 낮춰 보니 `싱가포르—카자흐스탄 협력 x1`
같은 헛것이 들어와 되돌렸다. **방법의 한계가 아니라 자료의 성질이다.**

**2. 1989~1996년 색인 제목에 글자 깨짐이 남아 있다**
구조(몇 장 몇 절)는 맞지만 제목 글자는 원문 대조가 필요하다.

**3. `links` 가 비어 있다**
항목 사이의 계승·개명·분화·소멸을 아직 판정하지 않았다.

**4. `stream` 배정은 기계로 검증할 수 없다**
제목·인용은 원문 대조로 걸러지지만 "같은 줄기인가"는 확인할 방법이 없다.
그 판단이 곧 이 프로젝트의 주장이므로, 화면은 연결을 보여줄 때 **양쪽 원문을
함께** 제시해야 한다.

**5. RAGAs 552개 중 5개만 답을 채웠다**

**6. 화면을 사람 눈으로 확인하지 못한 상태다**
구조와 글자는 코드로 검사했으나 보기에 좋은지는 미확인.

## 서술 규율 — UI 가 어떻게 생기든 지킨다

1. 모든 항목에서 **원문과 출처로 내려가는 경로**가 있어야 한다 (발간분·장·절·쪽)
2. **인용은 원문 그대로.** 요약·의역·윤문 금지
3. **우리 목소리로 인과를 주장하지 않는다**
   - ✗ "정권이 바뀌어서 순위가 바뀌었다"
   - ✓ "2025년 백서는 북핵을 4번에 두었다"
4. **집계 통계·자체 산출 순위를 만들지 않는다.** 화면의 숫자는 인쇄된 번호뿐
5. 교체가 없던 해도 **같은 형식으로** 볼 수 있어야 한다 (대조군)
6. 아직 채우지 않은 연도는 **비어 있음이 보여야** 한다
7. 정권을 **정당 색으로 칠하지 않는다**
8. **분류율은 정확도가 아니다.** "어딘가에 붙었다"와 "맞게 붙었다"는 다르다.
   표본을 뽑아 원문과 대조해야 오분류가 보인다

## 이 프로젝트가 스스로에게 건 규칙

1. **숫자를 지어내지 않는다.** 모든 값은 원본을 세어서 나온다
2. **연도로 분기하지 않는다.** 파일을 열어 성질을 보고 판단한다
3. **고칠 때마다 `docs/에러노트.md` 에 증상·원인·해결·배운 점을 남긴다**
4. **정확도를 밝히지 않은 결과를 내지 않는다.** 맞은 비율과 **답을 못 낸 비율**을
   함께 적는다
5. **"자료가 없다"는 원본을 열어본 뒤라야 적는다.** 아홉 해를 그렇게 적어
   두었는데 진짜로 없는 것은 하나도 없었다(에러노트 40번)

`docs/에러노트.md` 에 40건이 쌓여 있다. 고친 것마다 **왜 그랬는지**가 적혀 있어,
같은 함정을 두 번 밟지 않게 하는 장치다.

## 왜 파이프라인에 LLM 을 넣지 않는가

1. **212개는 사람이 감당하는 양이다.** LLM 은 사람이 못 하는 규모일 때 값을 한다
2. **연결 판정은 검증할 수 없다.** 제목·인용은 원문 대조로 기계 검증되지만
   "같은 줄기인가"는 기계가 확인할 방법이 없다
3. **그 판단이 곧 이 프로젝트의 주장이다.** 어차피 검수할 것이면 처음부터 직접 한다
4. **재현된다.** 규칙 + 표는 몇 년 뒤 돌려도 같은 결과가 나온다

초안을 모델이 만드는 것은 무방하다. 저장소에 남는 것은 **사람이 확인한 표**이고
빌드 과정에는 모델이 없다.
